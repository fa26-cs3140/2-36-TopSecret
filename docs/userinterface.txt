USER INTERFACE (Team Member D)

What it does:
After the agent logs in, the program shows an interactive menu. The menu
keeps running until the agent chooses Exit.

How to run:
  ./gradlew run        (or: java -jar build/libs/TopSecret.jar)
  Log in with your username and password, then use the menu below.

Menu options:
  1. List missions     Shows every mission title with a number.
  2. Read a mission    Asks for a mission number, then shows its title,
                       date, and brief.
  3. Search missions   Asks for a word or phrase and lists the titles of
                       missions whose brief contains it (case is ignored).
                       Prints "No matches found." if nothing matches.
  4. Exit              Prints "Goodbye." and ends the program.

After options 1 to 3, the menu is shown again.

Input errors (the program never crashes on bad input):
  - A menu choice other than 1 to 4: "Invalid choice. Enter 1, 2, 3, or 4."
  - A mission number that is not a number: "Error: 'abc' is not a number."
  - A mission number out of range: "Error: No mission with number 99."

Design:
  MissionMenu does not touch the database. It talks to the rest of the
  system only through two interfaces:
    MissionRepository  List<Mission> getAllMissions()
    MissionSearch      List<Mission> searchBriefs(String query)
  MissionStore extends both, and SqliteMissionStore (Member A) implements
  it, so TopSecret passes the same store in for both.
  The menu takes a Scanner and PrintStream instead of using System.in and
  System.out directly, so tests can type input and check the output.

Tests:
  MissionMenuTest (unit tests, fake database and search):
    - Exit ends the program
    - List shows numbered titles
    - Read shows the mission brief
    - Menu is shown again after reading
    - Bad mission number shows an error
    - Non-number shows an error
    - Invalid menu choice shows an error
    - Search shows matches
    - Search with no matches says so
    - Empty database shows a message
  MissionMenuIntegrationTest (real SQLite database and mission_briefs.tsv):
    - List shows all 100 missions from the database
    - Read shows a brief from the database
    - Search finds matches in the database, ignoring case
    - Search with no matches says so


HOMEWORK 5 USER INTERFACE (Team Member B: Homework5Menu)

Top menu after login (TopSecret):
  1. Existing Mission Menu    the Homework 4 menu above
  2. Homework 5 Records Menu  the menu below
  0. Logout

Records menu:
  1. Mission Briefs   2. Agents   3. Facilities
  4. View Audit Log            (admin only)
  5. Add User                  (admin only, username only)
  6. Manage User Access        (admin only, promote/demote others, not yourself)
  0. Back / Exit

Inside Mission Briefs, Agents, or Facilities:
  1. List entries     id and title/name of every entry
  2. Read an entry    all fields of one entry by id
  3. Add an entry     (admin) prompts for each field; the new entry is listed right away
  4. Update an entry  (admin) prompts for new values
  5. Delete an entry  (admin) refused if it would leave orphaned data
  0. Back

Fields asked for:
  Briefs:     title, date, text
  Agents:     name, date of birth, date of death (blank if alive), notes, facility id
  Facilities: name, abbreviation

Standard users only see list and read. Every read, add, update, and delete is
recorded in the audit log with the user and time.

Tests: Homework5MenuTest (unit, Mockito mocks for AuditLog and UserStore),
       Homework5MenuSqliteAuditLogTest (integration with the real database and audit log).
